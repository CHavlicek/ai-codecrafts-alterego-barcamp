# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start Vite dev server with HMR
- `npm run build` — production build to `dist/`
- `npm run lint` — ESLint across the repo (flat config in `eslint.config.js`)
- `npm run preview` — serve the built `dist/` locally

No test runner is configured. Do not add placeholder test scripts.

## Stack

- React 19 + Vite 8 (`@vitejs/plugin-react`, Oxc-based)
- Plain JSX (no TypeScript), ESM (`"type": "module"`)
- ESLint 9 flat config with `eslint-plugin-react-hooks` and `eslint-plugin-react-refresh`. The `no-unused-vars` rule ignores identifiers matching `^[A-Z_]` (React components, constants).
- The React Compiler is intentionally **not** enabled (see README).

## Project state

This repo is essentially a **fresh Vite React scaffold**. `src/App.jsx` and `src/main.jsx` are still the template-generated files — none of them represent real application code yet. Assume any feature work requires replacing the scaffold rather than extending it.

The app will be rebuilt as a Java + React/TypeScript full-stack application per the constitution's Technology Standards. Frontend work happens under `frontend/` (React 18+ TS strict + Vite), backend under `backend/` (Java 21 + Spring Boot 3 + Gradle Kotlin DSL). The top-level Vite scaffold that currently occupies the repo root will be absorbed into `frontend/` during the first feature.

## SpecKit workflow

This project uses [SpecKit](https://github.com/github/spec-kit) (`.specify/` + `.claude/commands/speckit.*.md`) for spec-driven feature development. The slash commands are the canonical entry points:

- `/speckit.constitution` — edit `.specify/memory/constitution.md` (currently still an unfilled template — populate it before it drives real decisions)
- `/speckit.specify` → `/speckit.clarify` → `/speckit.plan` → `/speckit.tasks` → `/speckit.implement`
- `/speckit.analyze` — cross-check spec/plan/tasks consistency
- `/speckit.checklist`, `/speckit.taskstoissues` — supporting flows

The shell scripts these commands invoke live in `.specify/scripts/bash/` (e.g. `create-new-feature.sh`, `setup-plan.sh`). Feature branches are numbered sequentially (`init-options.json: "branch_numbering": "sequential"`).

## Conventions to preserve

- Static assets referenced from JSX via `import` go in `src/assets/`; assets served as-is at the site root go in `public/` (e.g. `/icons.svg`, `/favicon.svg` — referenced by absolute path from JSX/HTML).
- Keep `index.html` at the repo root — Vite's entry point lives there, not in `public/`.
